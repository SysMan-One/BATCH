# BATCH -- подача пакетных заданий и управление ими

Выполняет сценарии оболочки пакетными заданиями: сценарий помещается
в очередь и выполняется позднее, без терминала, под управлением
постоянно работающего контроллера заданий.

Формат:

```
BATCH команда [параметр] [/квалификаторы]
```

Подача сценария не есть его выполнение. При подаче заводится запись
очереди с номером, и номер возвращается подавшему; процесс
порождается позднее, если и когда контроллер так решит. Пользователь
держится за запись, а не за процесс.

Задание, завершившееся неудачей, остаётся в очереди вместе со своим
журналом, чтобы в них можно было посмотреть. Успешное задание очередь
покидает. Именно поэтому команда SHOW без квалификаторов полезна: в
очереди остаётся то, что выполняется, и то, что не заладилось.

Команду можно сокращать до любого однозначного начала её имени, как и
квалификатор: SUBM есть SUBMIT, а DEL есть DELETE, тогда как S
отвергается — с него начинаются и SHOW, и SUBMIT.

Корневой каталог подсистемы берётся из переменной окружения
BATCH_ROOT, а если она не установлена — из значения, заданного при
сборке.

# SUBMIT -- поставить сценарий в очередь

Помещает сценарий оболочки в очередь для исполнения пакетным
заданием.

Формат:

```
BATCH SUBMIT спецификация-сценария [/квалификаторы]
```

Спецификация разворачивается в абсолютный путь при вводе команды.
Файл должен существовать и быть доступен для чтения и вам, и
контроллеру заданий.

Задание начинается в том рабочем каталоге, который был текущим при
подаче, а не в том, который будет текущим к началу исполнения.

Поскольку и спецификация файла, и квалификатор начинаются с косой
черты, довод считается квалификатором лишь тогда, когда текст до
знака равенства не несёт своей косой черты: /tmp/job.sh есть путь, а
/NAME=x есть квалификатор.

## /AFTER

Задаёт время, раньше которого задание начинаться не должно. Задание
удерживается до этого времени и освобождается само.

```
/AFTER=+1-02:00           через сутки и два часа
/AFTER=29-JUL-2026:03:00  определённый момент, по вашим часам
/AFTER=TOMORROW           полночь, с которой начинаются следующие сутки
```

Разностная форма есть +[суток-]чч[:мм[:сс]], опущенные поля считаются
нулевыми. Поле суток отличается от поля часов дефисом, который за ним
следует, и ничем иным:

```
+7          семь часов
+7-         семеро суток
+7-12:00    семеро суток и двенадцать часов
+:30        тридцать минут
+::45       сорок пять секунд
```

Ошибка здесь не обнаруживается, пока срок не истечёт, поэтому подача
называет время, с которого задание начнётся:

```
$ batch submit nightly.sh /AFTER=+7-
%BATCH-S-QUEUEDUNTIL, job nightly queued on SYS$BATCH as entry 4, holding until  9-AUG-2026 20:03:37
```

## /CPU

Привязывает задание к названным процессорам в записи taskset(1):
перечисление номеров и диапазонов через запятую.

```
/CPU=0-3,5,8-11
```

Без этого квалификатора задание наследует маску привязки контроллера
либо получает очередной процессор из пула, если контроллер запущен с
/LCORE. Список проверяется при вводе команды.

## /HOLD

Помещает задание в состояние Holding. Оно не рассматривается для
исполнения, пока не будет освобождено командой RELEASE.

## /KEEP

Сохраняет журнал задания после успешного завершения. По умолчанию
журнал успешного задания удаляется вместе с его записью очереди.

Журнал, названный квалификатором /LOG_FILE, не удаляется никогда: это
ваш файл, и распоряжаетесь им вы.

## /LOG_FILE

Называет файл, в который направляются стандартный вывод и стандартный
поток ошибок задания. Спецификация разворачивается в абсолютный путь
при вводе команды.

Такой файл открывается уже под личностью задания, поэтому решают
права того, от чьего имени оно работает, а не права контроллера.

По умолчанию журнал создаётся в том каталоге, откуда задание подано,
как это принято в OpenVMS, и называется по имени задания и номеру его
записи. Если писать туда нельзя, журнал уходит в подкаталог log
корневого каталога подсистемы.

## /NAME

Задаёт имя задания, до 63 знаков. По умолчанию имя задания есть имя
файла сценария без окончания .sh.

Имя обязано быть именем: косой черты и ссылки на родительский каталог
в нём быть не может — имя входит в спецификацию журнала, и такое имя
увело бы его из отведённого каталога.

## /PARAMETERS

Передаёт заданию до восьми значений.

```
/PARAMETERS=(full,/srv/data,verbose)
```

Каждое значение доступно сценарию дважды: как переменные окружения
P1 … P8 и как позиционные доводы $1 … $8. Значения передаются
интерпретатору отдельными элементами вектора доводов и никогда не
сливаются в командную строку, поэтому значение со знаками, значимыми
для оболочки, не может вызвать непредусмотренного исполнения.

Круглые скобки истолкует оболочка, вызывающая BATCH; заключайте весь
квалификатор в одиночные кавычки либо обходитесь без скобок.

## /PRIORITY

Задаёт приоритет задания в очереди, от 1 до 255, по умолчанию 100.
Контроллер выбирает ожидающее задание с наибольшим приоритетом; равные
по приоритету выбираются в порядке номеров записей.

Это приоритет в очереди. На приоритет планирования порождённого
процесса он не влияет и, когда задание уже выполняется, не значит
ничего.

## /QUEUE

Называет очередь, в которую помещается задание. По умолчанию — та, с
которой запущен контроллер.

## /RESTART

Предписывает выполнить задание снова, если контроллер был остановлен,
пока задание выполнялось. Такое задание возвращается в очередь при
следующем пуске; без квалификатора оно остаётся осиротевшим и
повторно не выполняется.

Процесс, оставшийся от прежнего экземпляра контроллера, не
разыскивается и не снимается: он живёт в своём сеансе и мог уже
отработать. Квалификатор обещает, что задание будет выполнено, а не
что оно будет выполнено однажды, — поэтому пишите его так, чтобы
двойное исполнение не вредило.

Заданию сообщают о перезапуске переменные BATCH_RESTART, принимающая
значения TRUE и FALSE, и BATCH_RESTARTS, считающая перезапуски.

## /USER

Выполняет задание от имени названного пользователя, а не подавшего.

```
/USER=sysman
```

Просить об этом вправе только привилегированный пользователь. Личность
устанавливает контроллер по тому, что о посылающем сообщает ядро, а не
по тому, что говорит запрос: утилита работает от имени вызвавшего её и
могла бы объявить себя кем угодно.

Всякое применение этого квалификатора и всякий отказ записываются в
журнал контроллера с указанием, кто просил и для кого:

```
%BATCH-S-RUNASUSER, job 1 submitted by uid 0 to run as sysman (uid 1000, gid 1000)
%BATCH-E-NOPRIVUSER, uid 1000 may not submit a job to run as root
```

Задание начинается в домашнем каталоге названного пользователя, а не
там, откуда подано, — туда его могут и не пустить; если такого
каталога нет, берётся корневой. Журнал уходит в подкаталог log
корневого каталога подсистемы: ответ о правах одного пользователя
ничего не говорит о другом.

## /RETAIN

Задаёт условие, при котором запись сохраняется после завершения
задания.

```
/RETAIN=ALWAYS      запись сохраняется всегда
/RETAIN=ERROR       только при неудаче; принято по умолчанию
/RETAIN=NEVER       не сохраняется, даже при неудаче
```

# SHOW -- показать очередь

Показывает записи пакетной очереди.

Формат:

```
BATCH SHOW [номер-записи] [/квалификаторы]
```

Номер записи показывает только её, в каком бы состоянии она ни была,
поэтому SHOW отдельной записи не зависит от /ALL, как зависит SHOW
очереди. Несуществующая запись отвергается, а не показывается пустой
очередью. Номер можно указать и квалификатором /ENTRY.

Без /ALL показываются задания выполняющиеся, снимаемые и сохранённые
после неудачи. Запись успешно завершённого задания очередь покидает,
поэтому такое задание не показывается даже с /ALL; подавайте его с
/RETAIN=ALWAYS, если запись должна остаться.

Столбец Elapsed — время от начала задания до его конца либо до
настоящего момента, пока оно выполняется.

Последний столбец говорит, чем задание кончилось: exit=n для
вернувшего такой код, signal=n для завершённого по сигналу. Для
задания, удержанного до срока, там стоит этот срок — у не
выполнявшегося задания кончиться нечему. Поэтому узнать время начала
можно без /FULL.

Привилегированный пользователь по владельцу не отбирается и в /EVERYONE
не нуждается: он вправе снять и освободить любую запись, а запись,
которой он может распорядиться, но не может увидеть, была бы хуже
бесполезной.

## /ALL

Добавляет к выводу задания в состояниях Pending и Holding.

## /EVERYONE

Показывает задания всех пользователей. По умолчанию — только свои.

## /FULL

Выводит полное описание каждого задания: владельца, приоритет,
привязку к процессорам, сценарий, рабочий каталог, журнал, отметки
времени, код завершения и параметры.

## /MANAGER

Показывает состояние контроллера заданий, а не содержимое очереди:
образ, которым он работает, его процесс и сколько времени он поднят,
обслуживаемый корневой каталог, предел заданий и сколько из него
занято, счёт заданий по состояниям, следующий номер записи и пул
процессоров, если он задан.

Стоящая на месте очередь выглядит одинаково и когда контроллер занят,
и когда он простаивает, и когда его нет вовсе, — а это первое, что
стоит узнать, если ничего не происходит.

## /QUEUES

Показывает очереди, а не задания: каждую с её пределом, с тем, что в
ней выполняется, ждёт и удержано, и приостановлена ли она.

## /PAGE

Удерживает вывод у нижнего края экрана и ждёт нажатия, для очереди
длиннее терминала.

Квалификатор есть любезность читателю у терминала и помеха программе,
читающей канал, поэтому применяется он лишь там, где есть чем
удерживать: при перенаправлении он молча пропускается, и вывод
получается ровно тем, каким был бы без него.

## /QUEUE

Ограничивает вывод заданиями названной очереди.

# DELETE -- снять запись с очереди

Снимает запись очереди, завершая задание, если оно выполняется.

Формат:

```
BATCH DELETE список-записей
```

Список пишется так, как его пишет DCL: числа и диапазоны через
запятую, скобки необязательны — `1,3,4` и `(1,3-5)` равно принимаются.
Каждый элемент применяется независимо от судьбы предыдущих, а команда
завершается с признаком неудачи, если не удался хоть один.

Выполняющемуся заданию посылается сигнал снятия всей его группе
процессов, и задание переходит в состояние Aborting; запись
обрабатывается по завершении процесса, а журнал сохраняется. В прочих
состояниях запись снимается сразу, а её журнал удаляется, если не был
указан /KEEP.

Снимать можно только свои задания; привилегированный пользователь —
любые.

# RELEASE -- освободить удержанное задание

Освобождает задание из состояния Holding.

Формат:

```
BATCH RELEASE список-записей
```

Список принимается так же, как командой DELETE.

Задание переходит в состояние Pending и становится готовым к
исполнению. Связанное с ним время /AFTER снимается, поэтому
освобождённое задание не удерживается второй раз.

Команда отказывает, если задание не находится в состоянии Holding.

# SET -- изменить атрибуты записи очереди

Изменяет атрибуты задания, стоящего в очереди, на месте. Запись
сохраняет номер и место в порядке; ничто не снимается и не подаётся
заново.

Формат:

```
BATCH SET ENTRY список-записей [/квалификаторы]
```

## ENTRY

Изменяет атрибуты названных записей. Список принимается так же, как
командой DELETE. Затрагиваются лишь те атрибуты, которые названы
квалификаторами; остальные остаются как были.

```
/PRIORITY=n         приоритет в очереди, от 1 до 255
/AFTER=время        не запускать раньше времени; /NOAFTER снимает его
/HOLD               удержать задание; /NOHOLD отпускает удержанное
/NAME=имя           имя задания
/RETAIN=ключ        ALWAYS, ERROR или NEVER, как у SUBMIT
/KEEP, /NOKEEP      хранить ли журнал успешно завершившегося задания
/RESTART, /NORESTART  выполнять ли задание снова после перезапуска
/CPU=список         процессоры, к которым привязано задание
```

Что можно изменить, зависит от состояния задания. У ожидающего,
Pending или Holding, можно изменить всё. У исполняющегося -- только
/RETAIN, /KEEP и /RESTART: остальное описывает уже состоявшийся
запуск. У сохранённого (Retained) изменить нельзя ничего: о нём
нечего больше решать. Запрос, называющий атрибут, который состояние
запрещает, отвергается целиком.

/HOLD и /AFTER действуют вместе так же, как при подаче. Удержанное
задание со временем отпускается, когда время наступает или когда
/NOAFTER его снимает; задание, удержанное одним /HOLD, ждёт RELEASE
или /NOHOLD. Поэтому /HOLD вместе с /NOAFTER означает: удержано, без
времени.

```
$ batch set entry 17 /PRIORITY=200
%BATCH-S-ENTMODIFIED, entry 17 modified: priority=200
$ batch set entry 17 /AFTER=TOMORROW /NAME=nightly2
%BATCH-S-ENTMODIFIED, entry 17 modified: after= 9-SEP-2026 00:00:00, name=nightly2
```

Новое имя задания меняет то, что показывают выводы, и ничего больше:
файл журнала был назван при подаче и имени не меняет.

# ANALYZE -- разобрать журнал очереди

Разбирает журнал очереди и сообщает, что с ним не так.

Формат:

```
BATCH ANALYZE [спецификация-журнала] [/DUMP]
```

Без спецификации разбирается журнал этой подсистемы.

Файл читается напрямую, а не через контроллер, поэтому команда
служит там, где контроллер не запускается, — то есть тогда, когда она
нужнее всего, — и равно служит на копии журнала, снятой с другой
машины.

Ничего не пишется. Найденный повреждённым журнал остаётся как есть:
что с ним делать — решать тому, кто запустил команду, а починка без
спроса была бы худшей неожиданностью.

Метка, которую эта редакция не назначает, называется вместе со
значением в шестнадцатеричном:

```
  entry 1: tag 4000, type 0, 6 octets not known to this revision: DE AD BE EF CA FE
```

Неисправностью это не считается — проходить мимо незнакомого и есть
то, что позволяет журналу пережить смену редакции, — но сказать об
этом стоит: журнал, написанный более поздней редакцией, и журнал,
тихо испорченный, выглядят одинаково, пока метки не названы.

Сперва сообщается заголовок, затем по строке на каждую неисправность:
запись, которая не раскодируется; отсутствующий, повторённый или
превышающий счётчик номер записи; состояние, не называющее состояния;
сценарий или рабочий каталог, не являющиеся абсолютными путями. При
находках команда завершается с признаком неудачи.

## /DUMP

Показывает и сами записи: номер, имя, размер, состояние, владельца,
приоритет, время постановки и исполняемый сценарий.

# SYNC -- дождаться конца задания

Ожидает конца задания и сообщает, чем оно кончилось.

Формат:

```
BATCH SYNC номер-записи [/TIMEOUT=секунд]
```

Предназначена для сценария, которому есть что делать после задания и
неоткуда узнать, когда оно готово. Ответ несёт код возврата, так что
читать вывод вызывающему не нужно:

```
0    задание удалось
1    задание не удалось, время вышло либо такой записи нет
```

```sh
batch submit nightly.sh /NAME=nightly
batch sync 17 /TIMEOUT=3600 || echo "ночное задание не задалось"
```

Запись, покинувшая очередь, считается успешной — очередь покидают
именно так: неудавшееся задание сохраняется. Номер, никогда не
выдававшийся, отличается от выданного и отработавшего по счётчику
выдачи и отвергается.

## /TIMEOUT

Прекращает ожидание по истечении названного числа секунд. Без него
ожидание не ограничено.

# QUEUE -- приостановить очередь или пустить её дальше

Удерживает работу очереди либо позволяет ей идти дальше.

Формат:

```
BATCH QUEUE имя-очереди /PAUSE
BATCH QUEUE имя-очереди /RESUME
```

Приостановленная очередь ничего не запускает. Записи её не трогаются,
а выполняющиеся задания доводятся до конца: приостановка — то, что
делают с очередью, задания которой должны подождать, а записи
остаться нетронутыми.

Просить об этом вправе только привилегированный пользователь:
приостановка удерживает работу всех, кто очередью пользуется, а
владение заданием ничего не говорит о самой очереди.

# PURGE -- снять записи завершившихся заданий

Снимает записи, оставшиеся от завершившихся заданий.

Формат:

```
BATCH PURGE [/QUEUE=очередь] [/CONFIRM]
```

Очередь, сохраняющая свои неудачи, нуждается в уборке: запись,
оставленная после неудавшегося задания, стоит, пока в неё не
посмотрят, — а посмотрели, и записи остались.

Берётся только завершившееся задание. Выполняющееся не трогается:
PURGE прибирает то, что кончилось, а не останавливает то, что нет.
Свои записи, если просит не привилегированный пользователь.

## /QUEUE

Ограничивает уборку названной очередью.

## /CONFIRM

Спрашивает, прежде чем действовать. Всё, кроме слова на Y, — отказ:
сделанное командой PURGE не отменить, а молчание не согласие.
Перенаправленный ввод считается подтверждённым — вопрос, ушедший в
файл, ждал бы нажатия, которого некому сделать, — и /NOCONFIRM
говорит то же явно.

# HELP -- показать эти сведения

Показывает сведения о команде этой подсистемы.

Формат:

```
BATCH HELP [тема [подтема ...]]
```

Без темы показывается весь текст. Подтема называется вслед за темой,
которой принадлежит:

```
$ batch help submit
$ batch help submit /after
$ batch help show /full
```

# STATES -- состояния, через которые проходит задание

Задание находится ровно в одном из следующих состояний.

```
Pending     может быть запущено и ждёт свободного места
Holding     удержано ключом /HOLD либо не наступившим сроком /AFTER
Executing   для него порождён процесс, и он работает
Aborting    послан сигнал снятия, и задание ещё не завершилось
Retained    завершилось, а запись сохранена для просмотра
```

Задание, вернувшее нулевой код и не имеющее /RETAIN=ALWAYS, очередь
покидает; всякое иное сохраняется.

# FILES -- что подсистема хранит и где

```
<корень>/batch.sock     сокет, на котором контроллер принимает запросы
<корень>/journal.dat    журнал очереди
<корень>/batchd.log     журнал самого контроллера
<корень>/log/           журналы заданий, для которых нет иного места
```

Корень есть /var/spool/batch, если при сборке не задано иное; утилита
берёт его из переменной окружения BATCH_ROOT.

Журнал очереди пишется во временный файл и переименовывается поверх
прежней копии, поэтому в недописанном виде он не наблюдается. Запись
его самоописывающая: последовательность помеченных значений, а не
образ структуры, — поэтому журнал переживает смену редакции
программы в обе стороны.
